# Brief for the independent reviewer

Give this brief, filled in, to a fresh reviewer (a subagent or a colleague) who has not seen the analysis code.

You are reviewing an analysis you did not write. Work read-only on the project; write your own scratch code in a separate scratch folder beside the project and remove it afterwards.

**You may read:** the report, the result tables, the figures and the raw input files:
- report: `<path>`
- result tables: `<paths>`
- figures: `<paths>`
- raw inputs: `<paths>`, with the data dictionary if there is one

**Do not read:** the analysis code, the notes, the step logs. Your recomputation has to be independent.

**Do exactly this:**

1. Recompute the headline numbers from the raw inputs with your own code: `<list the numbers of the summary and of each finding's headline, with their population>`. Agreement means equal after the rounding the report uses.
2. Read every number in the prose against the table or result file it comes from.
3. Read every claim against its evidence: a comparison stated for a population the table does not cover, a value shown as 0 where nothing could occur, a direction or "always/any" wording the numbers do not support, a causal verb on an association.
4. Read each chart title and annotation against the result table behind the chart.

**Report only demonstrated defects:** a number you recomputed and found different, a sentence a table contradicts, a wrong reference. For each: where it is, what is written, what is correct. Do not report style preferences or choices you would have made differently. If an item has no defect, say so plainly, and give the numbers you recomputed.
