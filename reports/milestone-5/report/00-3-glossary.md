# List of Terms

The terms below are listed in alphabetical order with their meaning in this report and the section that defines or
first needs them.

| Term | Meaning in this report |
| :---- | :---- |
| Add-drop period | The first weeks of a course in which students may still register for or drop it; the completion rate counts only students enrolled after it, which on OULAD means still registered at day 14 (Sections 1.2 and 2.1) |
| AQ Revision Log | The table that traces each change of AQ1–AQ4 from Milestone 1 to a finding in the data and to an entry of the Controlled Change Log (Section 3.2) |
| Attainable recall | The largest share of a run's non-completers that a list of length k can reach; below 1 when the run has more non-completers than k (Section 9, Appendix IX) |
| Base rate | The share of a run's enrolments who do not complete, which is also the share of non-completers on a random list (Section 9) |
| Baseline | The simple method or list that a candidate must beat to be worth its complexity, such as the rule-ranked list (baseline B2) for AQ3 (Sections 8.1 and 11.5) |
| Calibration | Agreement between predicted risks and observed rates; AQ3 would show probabilities only if it holds (Section 9.1) |
| Capacity | The number of students staff can contact at a review point: 3 or 5 per 20 students, that is 15% or 25% of a run's enrolments (Section 9) |
| Controlled Change Log | The numbered record C01–C18 of every change to the questions, data and methods, each with its reason and effect (Section 3.2) |
| Data cut-off | The day up to which a list or feature may use data: day 13 for the week-3 list and day 27 for the week-5 list (Section 3) |
| Decision option | A prescriptive statement drawn from observational data, offered as a hypothesis for the pilot rather than as a proven remedy (Section 11.5) |
| Development runs | The 9 module runs of 2013, on which AQ3 is developed and AQ2 is first estimated (Section 6) |
| Early-sign rule | By the data cut-off, a TMA or CMA due but not submitted, a TMA submitted late, or no platform activity in the previous seven days; the one rule of the project on OULAD and in the pilot (Section 2.1) |
| Enrolment | One student in one module run, the unit of every question (Section 3) |
| Fit rating | The rating of a question against its data: GREEN when the data are enough, YELLOW when the question must be narrowed, RED when a key concept, variable or intervention is missing (Section 5.1) |
| Fixed effects | Terms for each module run, so that students are compared only within the same run (Sections 8.1 and 11.3) |
| Frozen protocol | The evaluation choices of AQ3 and AQ4, fixed in advance so that the 2014 test runs are scored once (Sections 9.1 and 10) |
| Gate S1 | The success criterion of AQ3: the model's pooled normalised recall must exceed the rule list's, with the paired bootstrap interval above 0 and a sign-flip test p below 0.05 (Section 9) |
| Leakage | The use of information that would not exist at the moment of prediction (Section 7.1) |
| Leave-one-run-out folds | Development folds in which each 2013 run is held out once (Section 9.1) |
| Level 1, Level 2 | The compulsory level of Milestone 4, a modeling strategy and evaluation design, and the optional level, a prototype that is run; this project completed Level 1 and specified Level 2 without running it (Section 10) |
| Lift | The share of non-completers on a list divided by the run's base rate; 1 means chance (Section 9) |
| Module run (run) | One offering of an Open University module, named by its year and start month, B for February and J for October; the counterpart of a semester (Section 5) |
| Non-completion | A final result of Fail or Withdrawn; completion means Pass or Distinction (Sections 5 and 6) |
| Normalised recall | Recall at capacity divided by attainable recall, pooled over runs; the primary metric of AQ3 and AQ4 (Section 9) |
| Paired run | A 2014 test run whose module and start month also ran in 2013; 9 of the 13 test runs are paired (Section 9.1) |
| Penalised logistic regression | A logistic regression whose coefficients are shrunk towards zero to limit overfitting; the primary proposal for AQ3 (Section 8.1) |
| Prediction point | The end of day 13 or day 27, at which AQ3 estimates non-completion from the data up to the cut-off (Appendix VIII) |
| Recall at capacity | The share of a run's non-completers who are on its list of length k (Section 9) |
| Review point | A moment at which staff decide whom to contact, in weeks 3 and 5 (Sections 1.1 and 3) |
| Risk difference | The difference in later non-completion, in percentage points, between enrolments with and without an early sign, averaged within module run (Sections 8.1 and 11.3) |
| Rule FR1 | The fairness rule that flags a group for human review when its recall at capacity is more than 10 points below the other students' and the Holm-adjusted one-sided interval of the gap lies below 0 (Section 9.2) |
| Sensitivity run | A repeat of an estimate under a changed choice, to check that its conclusion holds (Section 11.3) |
| Sign-flip permutation test | A test of how often per-run differences as favourable would appear if the sign of each run's difference were random (Section 9, Appendix IX) |
| Status | The state of a final question: Answered, Partial, Deferred or Dropped (Section 3) |
| Test runs | The 13 module runs of 2014, kept for the single test of the AQ3 model, whose design no 2014 outcome informs (Section 6) |
| Traceability Matrix | The Final Project Traceability Matrix, which follows each final question in one row from the goal and KPI through data, preparation, method and evaluation to the decision, with GAP or N.A. where a link has no evidence (Section 11.1) |
| Wilson interval | The 95% score interval of a rate, used for the AQ1 rates (Section 8.1) |
