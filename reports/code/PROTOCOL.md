# Prototype protocol: implementation choices fixed before any result

Written 2026-11-11 (UTC), before any script of this folder produced a number. The Level 1 report of Milestone 4
(`reports/milestone-4/report/`, built as `N04_Milestone4_EN.docx`) already fixes the questions, populations,
predictor sets, baselines, metrics, splits and success criteria. This file adds only the implementation details that
Level 1 leaves open, so that none of them can be chosen after seeing a result. Each row names the Level 1 text it
completes. Nothing here changes a Level 1 choice.

## What Level 1 already fixes (not repeated in detail)

- Data: prepared dataset `OULAD-N04-prepared-1.0` of Milestone 3; unit = enrolment; target `non_completion`
  (final result Fail or Withdrawn); cut-offs day 13 and day 27; train = 9 runs of 2013, test = 13 runs of 2014.
- AQ1 grouped rates with intervals; AQ2 logistic association model with run fixed effects; AQ3 penalised logistic
  regression (primary) against the early-sign rule, a background-only model and a random list, with gradient-boosted
  trees and the extended predictor set as challengers; AQ4 top-k list per run from the AQ3 scores.
- Main operating point: day 27, 5 contacts per tutor group of 20.
- Gate S1, report S2, condition S3 and fairness rule FR1 (report Table 4.5); challenger margin of 0.03 pooled
  normalised recall and 7 of 9 folds (report Appendix III, step 4).

## Implementation choices of the prototype

| ID | Level 1 text it completes | Choice | Reason |
| :---- | :---- | :---- | :---- |
| P01 | Table 7.1 step 1 | Every script loads the prepared Parquet files through `common/lib.py`, which stops when a file's SHA-256 differs from `version_manifest.json`. Scripts write only inside `reports/code/`. The `model_ready_*` matrices are not used, because Level 1 refits every transform inside each fold. | Reproduce the data input; change no raw or prepared file |
| P02 | Appendix III steps 5–8; Change Log C14 | Order of work: AQ1 and AQ2 on the 2013 runs → AQ3 development on 2013 → second freeze → single test on 2014 → AQ4 lists and fairness → AQ2 replication on 2014 → AQ1 for the 2014 runs. `common/lib.py` refuses to return a 2014 outcome until `aq-3/results/freeze.json` exists, and appends every later access to `aq-3/logs/test-access.md`. | No test outcome can shape a choice; the access is recorded |
| P03 | Section 4.1 (capacity) | List length of a run: k = 5 × ceil(n / 20) (or 3 ×), n = enrolments registered at the cut-off, as in `capacity_by_run.parquet`. When a variant removes enrolments, k is recomputed from the remaining n. | Same rule as the prepared capacity table |
| P04 | Table 4.3 baseline | Rule-ranked list: score = number of signs (task missed, TMA late, inactive in the last 7 days; 0–3), ties by lower `activity_ratio_run`. Enrolments with no sign follow, also by lower activity ratio, so the list always reaches length k. | Level 1 wording, made complete for lists longer than the flagged group |
| P05 | – (ties) | Exact ties that remain at the edge of a list are broken by one fixed pseudo-random number per enrolment (`tiebreak_u`, seed 20261112, drawn in key order). The expected value under random tie-breaking is reported beside the S1 point estimates. | Outcome-independent, reproducible, same list for metrics and for AQ4 |
| P06 | Section 3.3 "penalised logistic regression" | L2 (ridge) penalty; scikit-learn `LogisticRegression`, solver lbfgs; grid C ∈ {0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1, 10}; intercept not penalised. | Ridge keeps every predictor in the equation, so each student's reasons come from stable, non-zero coefficients; an L1 penalty would switch correlated activity predictors on and off between folds |
| P07 | Appendix III step 3 "tuned by nested cross-validation" | Tuning criterion: log loss pooled over the inner leave-one-run-out validation rows; equal values go to the stronger penalty (LR) or the smaller model (trees). The step-4 comparison of configurations still uses the S1 metric. | Log loss is a proper scoring rule and smooth in the penalty, while recall at k takes few distinct values; it also rewards calibration, which S3 needs |
| P08 | Section 3.3 "gradient-boosted trees" | scikit-learn `HistGradientBoostingClassifier`, no early stopping, seed 20261112; grid: depth ∈ {2, 3, 4}, learning rate ∈ {0.05, 0.1}, trees ∈ {100, 200, 400}; module as a categorical feature (a module absent from training is read as missing), education as ordered code, other predictors untransformed. | Small grid as the brief asks (no large-scale tuning); native handling of missing values and categories |
| P09 | Section 3.3; Table 2.3 | Logistic preprocessing, refitted on the training rows of every fold: module and start month deviation-coded over the levels seen in training (unseen level = all zeros); education as ordered code 0–4; booleans 0/1; counts as log(1 + x); `registration_lead`, `activity_ratio_run`, `trend_last_week`, `days_since_last_click` not logged; nulls filled with the training median, with a missing-value indicator except for `registration_lead` in the primary set; every column standardised with training mean and standard deviation (a constant column becomes 0). `cma_score_mean_c` is left out. | Level 1 text made operational |
| P10 | Table 4.3 baseline | Background-only model B3 = the same penalised logistic pipeline on module, start month, previous attempts, credits, education and registration lead. | Same estimator, so the difference to M1 is the activity and task information alone |
| P11 | Appendix III step 4 | Choice rule: M1 (logistic, primary set) stays unless a challenger (M2 logistic extended, M3 trees primary, M4 trees extended) gains ≥ 0.03 pooled normalised recall at day 27, k = 5 per 20, and gains in ≥ 7 of 9 folds; if several qualify, the largest gain wins, and equal gains go to the simpler one (M2 before M3 before M4). The chosen configuration is used at both cut-offs. | Level 1 rule, completed for more than one qualifier |
| P12 | Appendix III step 5 | Second freeze: hyperparameters of every configuration tuned by leave-one-run-out on all 9 runs, then refitted on all 2013 rows. All five fitted configurations (B3, M1–M4) and the labels-available variant are frozen before the test, not only the chosen one; the others are scored on the test as context and cannot change the verdict. | The brief asks to compare with the Level 1 expectation and to show trade-offs; freezing them first keeps that honest |
| P13 | Section 4.2 "Uncertainty" | Two-level bootstrap: 2,000 replicates, seed 20261112; runs resampled, then enrolments within each sampled run; each list re-formed with the run's k. Sign-flip test: exact, all 2^13 sign assignments, statistic = mean per-run difference in normalised recall, one-sided. | Level 1 text made operational |
| P14 | Table 4.5 FR1; Table A.8 | Fairness bootstrap: the same two-level scheme with 5,000 replicates. Group recall = the group's non-completers on the lists ÷ the group's non-completers, summed over runs. One-sided p-value = share of replicates with difference ≥ 0; Holm step-down over the three confirmatory groups; flag = point gap below −10 points and Holm-adjusted p < 0.05. | 5,000 replicates give about 80 replicates in the smallest Holm tail (0.05 / 3) |
| P15 | Table 4.3 error analysis | Slices: activity none (`clicks_0c` = 0), low (`activity_ratio_run` < 0.5, some clicks), normal (≥ 0.5); previous attempts 0 or ≥ 1; late registration = registered after day 0 (`registration_lead` < 0); kind = Fail or Withdrawn; reachable = not unregistered in the 7 days after the cut-off. | Definitions fixed from predictors only |
| P16 | Table 4.2 (AQ2 signs) | Binary signs at day 27: (1) task missed (`rule_missed`), (2) TMA late (`rule_tma_late`), (3) inactive in the last 7 days (`inactive_last7`), (4) low activity = clicks below half the run median (`activity_ratio_run` < 0.5), (5) no activity before the start (`clicks_pre` = 0). Sensitivity for (4): thresholds 0.25 and 1.0. | Level 1 names the signs; a risk difference needs a yes/no definition of each |
| P17 | Table 4.2; Section 3.2 | AQ2 model: logistic regression (statsmodels GLM, maximum likelihood, HC1 robust standard errors) of non-completion on the five signs, run fixed effects, log(1 + previous attempts), log(1 + credits), and sign × module terms. A sign × module term is estimated only where the module holds at least 20 enrolments with the sign and 20 without it; elsewhere the sign is "not defined" in that module. Task signs enter only in runs with a task due by day 27. Adjusted risk difference = average over the population of predicted risk with the sign minus without it (other columns as observed), with a delta-method 95% interval; module-specific values average over that module's rows. | Level 1 text made operational; the minimum cell size avoids separation |
| P18 | Table 4.1 | AQ1 intervals: Wilson 95% (skill helper `stats_helpers.wilson_ci`). Second aggregation path: the raw OULAD tables `studentInfo.csv` and `studentRegistration.csv`, re-deriving "enrolled at day 14" independently. | Level 1 success criterion: two paths agree to the enrolment |
| P19 | Table 4.5 S3 | Probabilities are those of the frozen model as fitted; no recalibration on any 2014 row. Net benefit at threshold probabilities 0.2 to 0.7 in steps of 0.1. | Level 1 forbids recalibration on the test runs |
| P20 | – (independence) | The team's earlier prototype run (`reports/milestone-4/package/`, `reports/milestone-5/`) is not read while this prototype is built. After every result here is computed, its S1 numbers are compared with the earlier run as an independent cross-check, and any difference is explained or reported. | A second implementation that agrees is stronger evidence than a single one |

## Reading the results

A baseline may win (Level 1 report, Part 7). Every metric is reported, favourable or not. Results on the 2013
development folds serve the model choice only and are never presented as expected performance.
