# Prototype protocol: implementation choices of the rerun

Revised 2026-11-12 (UTC), before any script of this rerun produced a number. The Level 1 report of Milestone 4 (`reports/milestone-4/report/`, built as `N04_Milestone4_EN.docx`) fixes the questions, populations, predictor sets, baselines, metrics, splits and success criteria. This file adds the implementation details that Level 1 leaves open. Each row names the Level 1 text it completes. Nothing here changes a Level 1 choice.

## Status of this protocol: a rerun, written with the 2014 outcomes known

This folder was first produced on 11 November 2026 (git commit `11f4aca`). That first run wrote choices P01–P20 before its first result, froze its models at 2026-11-11T23:18:16Z and read the 2014 outcomes once, from 23:19:02Z. The team then compared its AQ1 and AQ2 reports with the Milestone 5 report of a team member (`reports/milestone-5/report/11-02-aq1-findings.md`, `11-03-aq2-findings.md`, `16-12-aq1-results.md`, `16-13-aq2-results.md`) and found five problems in AQ1 and AQ2. The owner asked for the whole prototype to be regenerated in one run, so that every table, log, figure and report agrees with the others.

Three facts follow, and every report of this folder states them where they matter.

1. **This protocol was not written before all results.** The analyst who revised it had read the first run's results, including every 2014 outcome table, and the Milestone 5 results. The rows P16–P18 and P21–P23 below were decided from that comparison. They are corrections of method and additions to reporting; none was chosen to move a verdict in a wanted direction, and the reports give each result under the first run's choice as well where the two differ.
2. **AQ3 and AQ4 are a reproduction of an unchanged design.** Rows P01–P15 and P19 are the first run's text, word for word. No model, grid, tuning criterion, tie-breaking rule, seed, bootstrap size, choice rule or fairness rule was changed, so the model choice cannot be shaped by the 2014 outcomes that have now been seen. The rerun makes a new freeze file because the pipeline is executed again from the first step; that freeze is a reproduction of the first run's freeze, not a second blind test. `common/compare_first_run.py` compares every regenerated AQ3 and AQ4 number with commit `11f4aca` and reports each difference.
3. **The guard of P02 documents order, not blindness.** `common/lib.py` still refuses a 2014 outcome until `aq-3/results/freeze.json` exists and still records every access. In this rerun that shows that the scripts ran in the Level 1 order. It no longer shows that the analyst had not seen the outcomes.

## What Level 1 already fixes (not repeated in detail)

- Data: prepared dataset `OULAD-N04-prepared-1.0` of Milestone 3; unit = enrolment; target `non_completion` (final result Fail or Withdrawn); cut-offs day 13 and day 27; train = 9 runs of 2013, test = 13 runs of 2014.
- AQ1 grouped rates with intervals; AQ2 logistic association model with run fixed effects; AQ3 penalised logistic regression (primary) against the early-sign rule, a background-only model and a random list, with gradient-boosted trees and the extended predictor set as challengers; AQ4 top-k list per run from the AQ3 scores.
- Main operating point: day 27, 5 contacts per tutor group of 20.
- Gate S1, report S2, condition S3 and fairness rule FR1 (report Table 4.5); challenger margin of 0.03 pooled normalised recall and 7 of 9 folds (report Appendix III, step 4).

| P06 | Section 3.3 "penalised logistic regression" | L2 (ridge) penalty; scikit-learn `LogisticRegression`, solver lbfgs; grid C ∈ {0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1, 10}; intercept not penalised. | Ridge keeps every predictor in the equation, so each student's reasons come from stable, non-zero coefficients; an L1 penalty would switch correlated activity predictors on and off between folds |

| P12 | Appendix III step 5 | Second freeze: hyperparameters of every configuration tuned by leave-one-run-out on all 9 runs, then refitted on all 2013 rows. | P15 | Table 4.3 error analysis | Slices: activity none (`clicks_0c` = 0), low (`activity_ratio_run` < 0.5, some clicks), normal (≥ 0.5); previous attempts 0 or ≥ 1; late registration = registered after day 0 (`registration_lead` < 0); kind = Fail or Withdrawn; reachable = not unregistered in the 7 days after the cut-off. | Definitions fixed from predictors only |
| P19 | Table 4.5 S3 | Probabilities are those of the frozen model as fitted; no recalibration on any 2014 row. Net benefit at threshold probabilities 0.2 to 0.7 in steps of 0.1. | Level 1 forbids recalibration on the test runs |

| P16 | Table 4.2 (AQ2 signs) | Binary signs at day 27: (1) task missed (`rule_missed`), (2) TMA late (`rule_tma_late`), (3) inactive in the last 7 days (`inactive_last7`), (4) low activity = clicks below half the run median (`activity_ratio_run` < 0.5), (5) no activity before the start (`clicks_pre` = 0). **Where a sign is defined:** (1) in the runs with a TMA or CMA due by day 27; (2) in the runs with a TMA due by day 27; (3)–(5) in every run. | P17 | Table 4.2; Section 3.2 | AQ2 model: logistic regression (statsmodels GLM, maximum likelihood, HC1 robust standard errors) of non-completion on the five signs, run fixed effects, log(1 + previous attempts), log(1 + credits), and sign × module terms. Inside the runs where a sign is defined, a module has its own slope when it holds at least 20 enrolments with the sign and 20 without it; modules below that size but with at least one enrolment on each side share one pooled slope; a module with no enrolment on one side has no term. **The support of a sign is the set of rows that carry one of its terms.** The adjusted risk difference is the average, over the support only, of predicted risk with the sign minus without it (other columns as observed), with a delta-method 95% interval; the unadjusted difference is computed on the same rows. Every estimate is printed with the number of rows it averages over, in the main, module, sensitivity and subgroup tables, and the script stops if an average includes a row outside the support. **Direction count:** the Level 1 criterion is applied as written (sign of each module's point estimate); beside it the tables give the number of modules whose interval excludes 0, name every module estimate whose interval includes 0 as "no detectable association in that module", and give the verdict under both readings. **Replication:** the 2014 − 2013 change of each adjusted difference is reported with a 95% interval from the two independent standard errors. | **Changed:** the first run averaged over every row of the runs where the sign was "defined", including rows of a module without a term, which entered as differences of exactly 0 and pulled the average toward 0 (late TMA in 2014: 3,521 CCC rows of 12,585). It also printed the row count of the whole table beside sensitivity estimates, counted a module estimate of +0.2 points with an interval of ±13 points as "same direction", and judged replication by whether intervals overlap |
| P18 | Table 4.1 | AQ1 intervals: Wilson 95% (skill helper `stats_helpers.wilson_ci`). The week-4 share is added over runs with a task due because a student with nothing due has an undefined missed-task status, not "no missed task" |

## Reading the results

A baseline may win (Level 1 report, Part 7). Every metric is reported, favourable or not. Results on the 2013 development folds serve the model choice only and are never presented as expected performance. For AQ1 and AQ2 the reports say which statements rest on choices made after the 2014 outcomes were seen.
